# ADR — bounded SmartLabs server adapters (#242)

Status: source implementation for independent review; NOT provider acceptance or production activation.
Parent: current Tanaghom master roadmap #221. This issue is independent of P5.5. Baseline: `b81e01e5c9d3b5486632569014008aabf11a01f1`.

## Decision

Expose provider-neutral `GemmaAdapter`, `TtsAdapter`, and `AsrAdapter` from `@tanaghom/agent-runtime/adapters`. Keep the SmartLabs origins, authentication header names, stock OmniVoice request parameters and environment translation in `providers/smartlabs.mjs`. Do not modify the existing certified n8n/Gemma structured-output flows, presenter providers, voice servers, or telephony infrastructure.

The dashboard integration is a request-scoped `smartLabsRuntime(request, trustedCapabilities)` factory in `lib/server/smartlabs-runtime.ts`, protected by `server-only` and the existing owner/operator authorization. It is not a new public HTTP endpoint. Do not cache this runtime across authenticated requests or derive trusted capabilities from browser/job JSON. Credentials are neither returned by the factory nor placed in `NEXT_PUBLIC_*` variables.

Backend config also supports operator-managed `SMARTLABS_GEMMA_API_KEY_FILE` / `SMARTLABS_API_KEY_FILE`; direct-plus-file is rejected even when direct is empty. Bounded regular-file reads remove at most one terminal LF/CRLF convention, never trim/normalize the credential. Missing enabled keys, malformed/ambiguous sources and unreadable/empty files fail closed without key/path/cause disclosure. Blank tracked examples contain no file paths. See the runbook for the exact contract.

All three enable flags default OFF. The authenticated factory denies disabled operations before reading assets, acquiring paid-attempt reservations or contacting a provider. Health is bounded Gemma `GET /models` only when explicitly enabled; TTS and ASR health are configuration-presence checks only. No synthesis, upload, balance probe or GPU job is a health check.

## Boundaries

* Gemma: fixed configured canary model, plain messages, temperature and max_tokens only; stream=false; one request per operation; 8,192 input tokens, 2,048 requested output tokens and 32 KiB serialized request maximum. The 60-second operation deadline includes asynchronous trusted token counting and the full HTTP response body. Usage, when supplied, is validated against budgets. Response bytes and model inventory count/IDs are bounded. Tool calling, schemas and structured-output certification are not supported.
* There is no verified local tokenizer/template installed by this change. The server must inject a trusted pinned exact message/token counter. Missing counter fails closed, and byte/character estimates are NOT token proof. A pure synchronous injected counter cannot be preempted by JavaScript timers; pin and benchmark it against bounded inputs before accepting it.
* No documented thinking-disable wire parameter was supplied. No chat_template_kwargs or guessed parameter is sent. Default dispatch fails closed without an explicit trusted `thinkingDisabled:true` attestation. This is an operator acceptance gate, not evidence that the client remotely disabled thinking.
* TTS: Arabic-first input of at most 500 Unicode code points; only OmniVoice, the stock smarttts2-xms-default voice and ar-SA dialect. CosyVoice3 remains stopped; there is no retry, fallback or cloning/reference-audio path. Client HTTP deadline 150 seconds, full body included. Actual RIFF/WAVE chunks, PCM16 mono 24 kHz, nonempty/non-silent samples, bounded size and duration and SHA-256 are verified before accepting audio. Output limit: 8 MiB and 120 seconds; no speech-quality claim follows from container validation.
* ASR: a currently approved controlled Creative audio version ID, never caller-supplied bytes, filenames, duration, MIME or external URLs. The factory joins the asset/version/job within the authenticated tenant and requires SQL status `approved` before private reads/uploads/audit, verifies its private object-key scope, bounds the actual file read, and the adapter verifies container/MIME/checksum and decoded duration. Maximum 25 MiB and 20 decoded seconds. Arabic only. Multipart contains exactly file and language=ar. WebM/MP4 are rejected.
* Native WAV support is deliberately PCM16 mono/stereo at 8–96 kHz with exact sample duration. Compressed MP3, Ogg Vorbis/Opus, FLAC and AAC/ADTS require a trusted injected inspector; the supplied decoder requires an existing absolute executable with a verified SHA-256. It uses forced demuxers and format/codec/pipe-only protocol allowlists, shell=false, one thread, a 10-second wall clock, bounded decoded output and a reduced environment. No executable, model or weight is installed. This is not a claim of an OS sandbox or certification of every container variation; deployment containment and decoder pin approval remain operator gates.
* HTTP is HTTPS-only outside explicit owned-loopback tests. Test mode itself cannot address a non-loopback origin. Redirects are rejected; credentials are not forwarded. Deadlines include body reads. Errors do not echo proxy bodies, headers, thrown causes or keys. Literal and JSON-escaped credential echoes are rejected. 200 is the contracted success status; uncontracted accepted/pending statuses are indeterminate. 400/401/402/403/413/422/429/503/504 are mapped safely. No automatic retry exists.

## Admission and indeterminate outcomes

A process-global gate is shared across factory/module instances per configured Gemma/TTS/ASR backend. It is held through HTTP body settlement AND paid-result validation; 429 Retry-After creates a local cooldown without a polling loop. Caller cancellation, timeout, transport uncertainty, response overflow, 5xx/proxy uncertainty and unaccepted paid 200 results (JSON/WAV/semantic validation) conservatively quarantine that process/backend rather than permitting a second explicit spend. Validated success releases; pre-contact validation and definitive auth/validation HTTP refusals remain determinate. There is no automatic retry.

This is NOT a distributed/global provider capacity certificate. There is no new Redis queue or admission table. Use one admission-owning application process unless a reviewed distributed admission arrangement is supplied. Process death releases local state and can leave remote work active: keep dispatch OFF on restart until an operator proves the previous provider work is settled. Do not restart to evade quarantine or assume a provider TTL that was not verified.

## Existing Creative integration

`tts.synthesizeToAsset({jobId,text})` consumes an already-existing, tenant-owned, actively claimed voice Creative job with enough remaining lease and a trusted existing worker pool. It does not create jobs, identities, lanes or a voice subsystem. It uses the existing controlled asset-version and completion functions, existing object-key/private storage scheme, and persists a draft Creative audio version. The private bytes are read back and checksummed; the committed version is read back before success. It does not approve/publish an asset.

TTS/ASR read the current database Creative enabled/not-emergency-stopped control via existing API SELECT rights before reservations/private reads/provider side effects. Missing/read-failed control fails closed. This is a read-boundary gate, not atomic exclusion against a subsequent stop commit. Smoke pauses with a durable same-source draft receipt for human approval through the existing decision API before separately invoking A1; it cannot re-spend G1/T1 and never autoapproves.

A reservation in existing api_idempotency_keys is autocommitted before paid TTS. Its scope uses the job's original requester, not a caller-supplied actor. Pending, failed or completed reservations prevent another paid attempt. Ambiguous database commit retains the private artifact for operator recovery rather than deleting potentially committed output. No exact external paid-create idempotency is claimed.

`asr.transcribe({sourceVersionId})` returns transcript metadata linked to that controlled source asset/version/job and writes the existing action audit with transcript hash/length, not full transcript. An uploaded asset can have no source job; do not manufacture a replacement identity/job for it.

Migration 0047 only extends existing Creative MIME/object-key and controlled-version support for Ogg/FLAC/AAC. It introduces no table, identity, queue, role or new privilege. Both up/down refuse unsafe role attributes/memberships/schema creation and worker direct table/column privileges (including jobs/controls/provider calls and destructive privileges) across Creative tables and brand-kit tables; intended API SELECT is preserved while API write/destructive rights are refused. No grants are repaired. Up/down require their exact migration baselines. Down refuses used immutable new-format versions rather than deleting/reclassifying them. Voice registry enablement and unrelated provider selectors are unchanged.

## Billing and evidence

The contract did not specify billing header names. None are guessed. A trusted pure `readBilling(headers)` mapper may be installed only after its SmartLabs mapping is verified; the transport projects finite nonnegative numeric creditsUsed/balance only. Headers, strings, extra fields and thrown mapper causes are never returned. Unavailable or invalid billing is null, not zero or fabricated cost.

Offline fixtures exercise actual modules, real owned-loopback sockets, actual private file reads/writes, a native pinned decoder and a network-isolated disposable PostgreSQL fixture. They are provider stubs, not real SmartLabs acceptance. Actual latency/credits, Arabic quality, exact tokenizer/template/context compatibility, thinking state and deployment/bundle isolation remain separate acceptance gates. See the runbook and external native evidence handoff. No commit, PR, merge or activation is performed by this worker.
